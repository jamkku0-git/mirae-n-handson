# 승인 체크리스트 v1

v1 · 2회차 (2026-10-06)
- "충분하다" · "적절하다" · "심각한 문제가 없다" 같은 항목을 예/아니오로 답할 수 있는 문장으로 바꿨다.
- 치명을 비밀값 노출 · 인증 우회 · SQL 인젝션 · 업로드 취약점 · 다운로드 취약점 다섯 가지로 정의했다.
- 새 public 메서드 테스트 · 범위 밖 변경(import 정리만 허용) · 컨벤션 반려/경고 기준을 추가했다.

AI 가 만든 변경분 · 외주사 PR 을 머지하기 전에 리뷰어가 대조하는 목록이다. 네 기준이 **모두** 충족되어야 승인이다. 하나라도 미충족이면 반려.

## 심각도 정의

- **치명** — 아래 다섯 가지 중 하나에 해당하는 문제. 1건이라도 있으면 반려.
  1. 비밀값 노출 (비밀번호 · 토큰 · 키의 리터럴, 로그 출력, 응답 노출)
  2. 인증 우회 (인증 · 인가 검사를 지우거나 건너뛰는 변경)
  3. SQL 인젝션 (SQL 문자열 조립)
  4. 업로드 취약점 (파일 형식 · 크기 · 저장 경로 검증 없는 업로드)
  5. 다운로드 취약점 (사용자 입력 경로로 파일을 읽어 내려주는 코드, 경로 이탈 `../` 방어 없음)
- **경고** — 치명은 아니지만 다음 변경에서 사고가 될 가능성이 있는 문제(네이밍 · 포맷 · 반복 코드 등). 승인 · 반려에 영향을 주지 않고 이슈 목록에 남긴다.
- **제안** — 더 나은 방법이 있다는 의견. 승인 · 반려에 영향을 주지 않는다. 목록으로만 남긴다.

이슈 한 건은 심각도 · `파일:줄번호` · 근거 · 수정 방향 네 항목으로 적는다. 근거 줄번호를 댈 수 없는 지적은 "확인 필요"로 따로 둔다.

## 1. 테스트 통과

- [ ] 변경된 모듈의 테스트 명령을 실제로 실행했다(실행하지 않고 통과라고 쓰지 않는다).
- [ ] 실행 결과에 실패 · 오류가 0건이다.
- [ ] 새로 추가한 public 메서드 · 엔드포인트마다 그것을 호출하는 테스트가 1개 이상 있다(getter · setter · 생성자 같은 접근자는 제외).
- [ ] 테스트 디렉터리에서 새 메서드 이름 또는 새 URL 을 검색하면 1건 이상 나온다.
- [ ] 이관 코드 변경이라면 `characterization` 을 실행했고 통과 · 실패 수가 기록돼 있다(이관 코드가 아니면 해당 없음).
- [ ] 기존 테스트를 지우거나 건너뛰게(`skip`, `@Disabled`) 바꾼 곳이 없다.

## 2. 치명 이슈 0건

- [ ] 비밀번호 · 토큰 · 키가 코드 · 설정 · 테스트 픽스처에 리터럴로 들어 있지 않다(실습용 더미 `app-pass` 는 예외).
- [ ] 비밀값 · 학생 식별자(`STU-…`) · 이메일이 로그나 응답에 출력되지 않는다.
- [ ] 인증 · 인가 검사를 지우거나 건너뛰는 변경이 없다.
- [ ] SQL 을 문자열로 이어 붙여 만드는 곳이 없다(파라미터 바인딩 사용).
- [ ] 파일 업로드가 새로 생겼다면 형식 · 크기 · 저장 경로를 서버에서 검증한다(업로드가 없으면 해당 없음).
- [ ] 파일 다운로드가 새로 생겼다면 사용자 입력 경로에 `../` 이탈 방어가 있다(다운로드가 없으면 해당 없음).

## 3. 요청 범위 이탈 없음

- [ ] 요청 문장이 한 문장으로 확인되었다(없으면 판정하지 않고 먼저 묻는다).
- [ ] 변경 파일 목록의 모든 파일이 요청 문장으로 설명된다.
- [ ] 요청 문장으로 설명되지 않는 변경은 같은 파일 안의 import 정리뿐이다(그 외 변경이 하나라도 있으면 아니오).
- [ ] 의존성 추가 · DB 스키마 변경 · 설정 파일 변경이 있다면 요청에 포함돼 있었다.
- [ ] 데이터를 지우거나 덮어쓰는 코드가 새로 생겼다면 요청에 그 내용이 명시돼 있다.

## 4. 컨벤션 준수

- [ ] 팀 `CLAUDE.md` 의 코딩 컨벤션과 금지 사항을 대조했다(`convention-check` Skill 이 있으면 그 결과를 쓴다).
- [ ] 컨트롤러에서 Repository · SQL 을 직접 호출하는 곳이 없다.
- [ ] 예외를 잡고 아무 처리 없이 넘기는 빈 `catch` 가 없다.
- [ ] `System.out` · `console.log` 같은 임시 출력이 남아 있지 않다.
- [ ] 루프 안에서 Repository 를 호출하는 곳(N+1)이 없다.

위 네 항목 위반(컨트롤러 계층, 빈 catch, 임시 출력, N+1)은 **반려** 사유다. 네이밍 · 들여쓰기 · 줄 길이 같은 나머지 컨벤션 위반은 **경고** 로 이슈 목록에만 남기고 반려 사유로 쓰지 않는다.

## 판정 형식

첫 줄에 `판정: 승인` 또는 `판정: 반려`. 이어서 네 기준의 충족 · 미충족 표, 그다음 이슈 목록(심각도 · `파일:줄번호` · 근거 · 수정 방향). 코드는 수정하지 않는다.
