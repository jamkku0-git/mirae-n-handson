# 머지 전 검증

검증 대상: $ARGUMENTS

- 인자가 비어 있으면 `git diff upstream/main...HEAD` 를 대상으로 삼는다.
- 경로는 모두 저장소 루트 기준이다(이 Skill 폴더 기준이 아니다).
- 판정 기준과 심각도 정의는 저장소 루트의 `templates/approval-checklist.md` 를 따른다. 항목을 여기에 옮겨 적지 않는다.

## 1. 요청 범위 확인

- 무엇을 요청한 변경인지 한 문장으로 확인한다.
- 요청 문장이 주어지지 않았으면 **판정하지 말고** 먼저 사용자에게 묻는다.

## 2. 변경 파일 목록과 diff 읽기

- 목록 먼저: `git diff --stat <대상>`. patch 파일이면 `git apply --stat <파일>`.
- 그다음 파일마다 diff 를 읽는다: `git diff <대상> -- <파일>`.
- 변경 파일을 모듈별로 나눈다: `modern/api/`, `modern/web/`, `characterization/`, 그 밖.

## 3. 체크리스트 대조

- 저장소 루트의 `templates/approval-checklist.md` 를 Read 로 읽는다.
- 항목마다 충족 · 미충족 · 확인 필요 중 하나로 표시한다.
- 컨벤션 항목은 저장소 루트의 `CLAUDE.md` 를 기준으로 본다.

## 4. 테스트 실행

변경된 폴더의 테스트만 실행한다. 명령은 저장소 루트에서 시작한다.

| 바뀐 폴더 | 명령 |
|---|---|
| `modern/api/` | `cd modern/api && ./gradlew test` |
| `modern/web/` | `cd modern/web && npm test` |
| 이관 코드 (아래 기준) | `cd characterization && npm test` (레거시 대상) 와 `cd characterization && TARGET_BASE_URL=http://localhost:8080 npm test` (새 API 대상) |

이관 코드는 아래 중 하나에 해당하는 변경이다. 짐작으로 정하지 않는다.

- `characterization/lib/target.mjs` 의 `PATH_ALIASES` 에 오른쪽 값으로 적힌 새 API 경로(예: `/api/items/search`, `/api/units`)를 처리하는 `modern/api` 코드(그 경로의 Controller 와 그 Controller 가 호출하는 Service · Repository)가 바뀌었다.
- `characterization/lib/` 나 `PATH_ALIASES` 자체가 바뀌었다.

- 결과는 **통과 · 실패 수와 실패한 테스트 이름만** 남긴다. 전체 로그를 대화에 싣지 않는다. 필요하면 출력을 `tail` · `grep` 으로 줄여서 읽는다.
- 대상 서버가 꺼져 있거나 의존성이 없어 실행할 수 없으면 "실행하지 않음 (사유)"로 적고 사용자에게 기동을 요청한다.
- 스냅샷을 갱신(`-u`)하지 않는다.

## 5. 승인 기준 판정

- 네 기준(테스트 통과 / 치명 이슈 0건 / 요청 범위 이탈 없음 / 컨벤션 준수)을 하나씩 판정한다.
- 하나라도 미충족이면 반려다.
- 이슈가 0건이면 경고 · 제안 수준까지 한 번 더 확인한다.

## 6. 출력 형식 (순서 고정)

```
판정: 승인 | 반려

| 기준 | 결과 | 근거 |
|---|---|---|
| 테스트 통과 | 충족 / 미충족 | 실행 명령과 통과 · 실패 수, 실패한 테스트 이름 |
| 치명 이슈 0건 | 충족 / 미충족 | 치명 이슈 번호 |
| 요청 범위 이탈 없음 | 충족 / 미충족 | 요청 문장 vs 변경 파일 목록 |
| 컨벤션 준수 | 충족 / 미충족 | 위반 이슈 번호 |

이슈 목록
| # | 심각도 | 파일:줄번호 | 근거 | 수정 방향 |
|---|---|---|---|---|
| 1 | 치명 / 경고 / 제안 | `modern/api/.../Foo.java:42` | … | … |
```

- 이슈 한 건은 심각도 · `파일:줄번호` · 근거 · 수정 방향을 이 순서로 모두 채운다.
- "확인 필요" 항목은 이슈 목록 아래에 따로 적고, 무엇을 더 보면 판정할 수 있는지 한 줄 덧붙인다.

## 7. 하지 말 것

- 코드를 수정하지 않는다. 판정과 수정 방향만 보고한다.
- 근거 줄번호를 댈 수 없는 지적은 이슈로 올리지 않고 "확인 필요"로 남긴다.
- 테스트를 실행하지 않고 통과했다고 쓰지 않는다.
