# 장애 원인 분석(RCA)

- 대상: `incident-logs/$ARGUMENTS/` (원본은 읽기만 한다)
- 결과: `docs/rca/$ARGUMENTS.md`
- 경로는 모두 저장소 루트 기준이다. 예시 리포트: `docs/rca/a-connection-pool.md`

## 1. 수집 범위

- 파일을 통째로 읽지 않는다. `wc -l` · `head` · `tail` · `grep -c` · `grep -n` · `awk` 로 필요한 부분만 본다.
- 파일마다 줄 수, 기록 기간, 시각 형식, 타임존을 표로 적는다. 타임존 표기가 없으면 다른 파일과의 분당 건수 일치 같은 근거로 판단하고 근거를 적는다.
- 모든 시각을 한 타임존(KST)으로 맞추는 변환 규칙을 적는다.
- 이상 신호를 분 단위로 집계해 첫 실패 · 마지막 실패를 찾고, 앞뒤 여유를 이유와 함께 정해 수집 범위를 확정한다. 이 단계에서는 원인을 해석하지 않는다.

## 2. 타임라인

- 수집 범위 안의 모든 파일을 한 시간축으로 합친다. **모든 줄에 `파일:줄번호`** 를 붙이고 원문 발췌를 함께 적는다.
- 반복 메시지는 "첫 발생 시각, 이후 N건/분"으로 묶는다.
- 같은 초이거나 몇 초 차이로 선후를 단정할 수 없으면 **(선후 불확실)** 로 표시한다.
- 첫 실패와 최다 오류보다 앞서면서 평소와 다른 줄을 ★ 로 표시한다. 해석은 넣지 않는다.

## 3. 가설

- 최다 오류 · 타임아웃 메시지는 "증상"으로 따로 적는다.
- 서로 다른 계층(코드 · DB · 트래픽 · 인프라 등)에서 가설을 **2개 이상** 세운다.
- 가설마다 지지 근거(타임라인 줄), **반증 조건**(이게 보이면 틀렸다), **확인 방법**(실행할 명령 · 볼 파일)을 적는다.

## 4. 반증과 판정

- 먼저 로그로 반증을 시도한다. 실행한 명령과 출력을 그대로 실행 기록에 남기고, 결과는 숫자로 적는다.
- 판정은 "유지 / 기각 / 판단 불가(로그 부족)"로 하고, 판단 불가면 무엇이 있어야 판단되는지 적는다.
- 유지된 가설은 로그의 단서(클래스명 · 풀 이름 · 수치)로 코드 · 설정을 찾아 대조한다. 설정값은 파일에서 읽은 값만 쓴다.
- 대조 결과로 채택 · 기각을 최종 판정한다. 확신 수준과 남은 불확실성을 함께 적는다.

## 5. 리포트 작성

`docs/rca/$ARGUMENTS.md` 에 다음 순서로 쓴다.

1. 요약 — 무슨 일, 영향, 원인, 확신 수준
2. 수집 범위 · 타임라인 · 가설과 검증(1 ~ 4단계 결과)
3. 원인 — 인과 순서대로 문장 번호(C1 …)를 붙인다
4. 근거 로그 줄 — 문장 번호별 `파일:줄번호` 와 발췌
5. 수정안 — 지금 적용할 것. 코드는 고치지 않고 제안만 한다
6. 재발 방지 — 규칙 · 테스트 · 격리 같은 구조적 장치
7. 모니터링 항목 — 지표, 임계값, 이번에 울렸을 시각
8. 확인하지 못한 것 — 이유와 다음을 위해 남길 로그

## 6. 마스킹

리포트를 저장하기 전에 `.claude/skills/rca/masking-rules.md` 의 규칙을 적용하고, 리포트 끝에 종류별 적용 건수를 한 줄로 적는다.

## 하지 말 것

- 로그에 없는 줄을 인용하지 않는다. 인용한 `파일:줄번호` 는 실제로 열어 확인한 것만 쓴다.
- 가장 많이 나온 오류를 곧바로 원인이라고 부르지 않는다.
- 원본 로그와 소스 코드를 수정하지 않는다.
- 마스킹 대응표(원본 ↔ 별칭)를 파일로 남기지 않는다.
- 마스킹 전 원본을 임시 폴더에 복사해 두지 않는다.
