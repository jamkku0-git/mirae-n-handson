# legacy/item-bank-php 비즈니스 규칙 후보

> 분석 범위: 문항 검색(`search.php`), 문항 등록(`register.php`), 단원 목록(`units.php`), 스키마 · 뷰(`db/mariadb/init/01-schema.sql`).
> 선행 문서: [ARCHITECTURE.md](ARCHITECTURE.md) · [ERD.md](ERD.md)
> 근거 표기는 `파일:줄번호` 이다. 경로가 `db/` 로 시작하지 않으면 `legacy/item-bank-php/` 기준이다. `vendor/` 는 열지 않았다.
>
> 확신도
> - **확실**: 코드의 조건문 · SQL 로 확인했다.
> - **추정**: 이름이나 주석으로 짐작했다.
>
> 2026-09-29 에 로컬 compose(`--profile php`)로 일부 동작을 실행해 확인했다. 결과는 [9. 실행 확인 기록](#9-실행-확인-기록)에 있고, 해당 규칙의 비고에 "실행 확인"으로 표시했다.
>
> 이 문서의 규칙은 모두 코드로 확인한 것이다. 근거가 주석뿐인 내용은 규칙으로 올리지 않고 [5. 주석만 있음](#5-주석만-있는-내용)에 모았다.

**문항 수정 기능은 없다.** 이 모듈에는 `UPDATE` 문도, 수정 화면도 없다(`grep -iE "edit|update|수정"` 결과 `register.php:87` 의 `FOR UPDATE`, `:93` 의 `updated_at` 뿐). 그래서 "수정 시 검증" 규칙은 없다.

## 1. 문항 검색 — 조건 조합 (`search.php` `buildSearchQuery`)

### BR-01 조건 결합
- 규칙: 키워드 · 단원 · 난이도 · 태그 조건이 여러 개 주어지면, 모두 AND 로 묶어 전부 만족하는 문항만 조회한다.
- 근거: `search.php:44`, `:98`, `:118`, `:215`, `:218`, `:244`
- 근거 코드:
  ```php
  $where    = " WHERE 1=1";
  $where .= " AND unit_code = ?";
  $where .= " AND level = ?";
  ```
- 확신도: 확실
- 비고: OR 조합이나 여러 값 선택은 없다(BR-15 참고).

### BR-02 공개 문항만 검색
- 규칙: 검색은 `v_item_public` 뷰를 조회하므로 `status = 'A'` 인 문항만 결과에 나온다.
- 근거: `search.php:522`, `db/mariadb/init/01-schema.sql:70`
- 근거 코드:
  ```php
  $from   = " FROM v_item_public";
  ```
  ```sql
  WHERE i.status = 'A';
  ```
- 확신도: 확실
- 비고: 같은 "공개 = `'A'`" 조건이 `units.php:17` 에도 따로 구현돼 있다(BR-28). `'A'` 는 매직 값이다.

### BR-03 난이도를 비우면 난이도 5 제외
- 규칙: 난이도 값이 비어 있으면 `level < 5` 조건을 붙여, 난이도 5 문항을 결과에서 뺀다.
- 근거: `search.php:213-216`
- 근거 코드:
  ```php
  // 난이도 값이 비어 있으면 전체 난이도 검색 (1~5 모두 포함)
  if ($level == '') {
      $where .= " AND level < 5";
  ```
- 확신도: 확실
- 비고:
  - **주석과 코드가 다르다.** 주석(`search.php:213`)은 "1~5 모두 포함" 이라고 하지만, 코드는 5 를 뺀다. 파일 머리 주석도 `level : 난이도 (1~5, 빈값 허용)` 이다(`search.php:8`).
  - 폼의 "전체" 선택지가 빈값이다(`search.php:192`). 그래서 **조건 없이 검색해도 난이도 5 는 나오지 않는다.**
  - 시드 주석에 `status='A' AND level<5 는 정확히 20건 (검색 화면 페이지 크기와 같다)` 가 있다(`db/mariadb/init/02-seed.sql:34`). 시드가 이 동작을 전제로 만들어졌다.
  - 숫자 `5` 는 매직 넘버다.
  - 실행 확인: 조건 없이 검색하면 20건이 나온다. `level=5` 로 검색하면 6건이 나온다(9장 C1 · C2).
  - 이 비교만 `==`(느슨한 비교)이고, 다른 비교는 `===` 를 쓴다. 다만 `$level` 은 문자열로 변환돼 있어서(`search.php:63`) 결과는 같다.

### BR-04 난이도 1~5 는 정확히 일치
- 규칙: 난이도 값이 `1`~`5` 중 한 자리 숫자이면, 그 난이도와 같은 문항만 조회한다.
- 근거: `search.php:217-221`
- 근거 코드:
  ```php
  else if (preg_match('/^[1-5]$/', $level)) {
      $where .= " AND level = ?";
  ```
- 확신도: 확실
- 비고: 이 분기에서는 5 도 조회된다. 난이도 5 문항은 `level=5` 로 명시해야만 볼 수 있다.

### BR-05 범위 밖 난이도는 정수로 바꿔 그대로 비교
- 규칙: 난이도 값이 비어 있지 않고 `1`~`5` 한 자리도 아니면, 경고를 띄운다. 그리고 `(int)` 로 바꾼 값과 같은 문항을 조회한다.
- 근거: `search.php:223-229`
- 근거 코드:
  ```php
  $warnings[] = '난이도는 1~5 사이여야 합니다.';
  $where .= " AND level = ?";
  $values[] = (int)$level;
  ```
- 확신도: 확실
- 비고:
  - PHP `(int)` 변환 규칙 때문에 경고가 떠도 결과가 나오는 경우가 있다. `03`, `3.5`, `3abc` 는 모두 3 이 되어 난이도 3 문항이 조회된다. `abc` 는 0 이 되어 0건이다.
  - 실행 확인: `level=03` · `level=3.5` 는 경고와 함께 5건(`level=3` 과 같음), `level=abc` 는 0건이다(9장 C5~C8).
  - 등록 쪽(BR-35)은 같은 값을 거부한다. **같은 "난이도 1~5" 규칙이 화면마다 다르게 처리된다.**

### BR-06 키워드는 앞뒤 공백을 빼고 100자까지
- 규칙: 키워드는 앞뒤 공백을 제거한다. 100자를 넘으면 100자로 자르고 경고를 띄운다.
- 근거: `search.php:85-89`, `:494`
- 근거 코드:
  ```php
  if (mb_strlen($q, 'UTF-8') > 100) {
      $q = mb_substr($q, 0, 100, 'UTF-8');
  ```
- 확신도: 확실
- 비고: 같은 100 이 HTML `maxlength="100"` 에도 따로 적혀 있다(`search.php:494`). 매직 넘버다.

### BR-07 키워드는 제목 또는 지문에서 부분 일치
- 규칙: 키워드가 있으면 제목(`title`) 또는 지문(`stem`)에 키워드가 포함된 문항을 조회한다.
- 근거: `search.php:97-98`
- 근거 코드:
  ```php
  $like = '%' . $q . '%';
  $where .= " AND (title LIKE ? OR stem LIKE ?)";
  ```
- 확신도: 확실
- 비고: `%` · `_` 를 이스케이프하지 않는다. 따라서 이 문자들은 와일드카드로 동작하고, 경고만 띄운다(`search.php:94-95`).

### BR-08 한 글자 키워드는 경고만 띄움
- 규칙: 키워드가 한 글자이면 경고를 띄운다. 검색은 그대로 한다.
- 근거: `search.php:91-92`
- 근거 코드:
  ```php
  if (mb_strlen($q, 'UTF-8') === 1) {
      $warnings[] = '키워드가 한 글자라 결과가 많을 수 있습니다.';
  ```
- 확신도: 확실
- 비고: 최소 길이 제한은 없다.

### BR-09 단원은 단원 코드로 정확히 일치
- 규칙: 단원 값이 있으면 `unit_code` 가 그 값과 같은 문항만 조회한다. 코드 형식이 틀리거나 소문자가 섞여 있으면 경고만 띄우고 입력값 그대로 조회한다.
- 근거: `search.php:109-120`
- 근거 코드:
  ```php
  if (!preg_match('/^[A-Za-z][0-9]{1,2}-[0-9]{1,2}$/', $unit)) {
  if ($unit !== strtoupper($unit)) {
  $where .= " AND unit_code = ?";
  ```
- 확신도: 확실
- 비고:
  - 형식 정규식 `[A-Za-z][0-9]{1,2}-[0-9]{1,2}` 는 매직 값이다.
  - 경고 문구는 "대문자로 입력하세요" 이다. 그런데 `unit.code` 의 콜레이션이 `utf8mb4_unicode_ci` 라서(`db/mariadb/init/01-schema.sql:18`) `m5-1` 도 `M5-1` 과 일치한다. 실행 확인: `unit=m5-1` 로 검색하면 "대문자로 입력하세요" 경고와 함께 `M5-1` 과 같은 5건이 나온다. 단원명 조회(`search.php:125`)도 성공한다(9장 C3 · C4). **경고 문구와 실제 동작이 다르다.**
  - 검색은 단원을 **코드**로 찾고, 등록(BR-34)은 **id** 로 찾는다.

### BR-10 등록되지 않은 단원 코드는 경고
- 규칙: 입력한 단원 코드가 `unit` 테이블에 없으면 "등록되지 않은 단원 코드" 경고를 띄운다. 조회는 그대로 하며, 결과는 0건이다.
- 근거: `search.php:125`, `:141-143`
- 근거 코드:
  ```php
  $stmt = $conn->prepare("SELECT name, grade FROM unit WHERE code = ?");
  if ($unitName === '') {
      $warnings[] = '등록되지 않은 단원 코드입니다: ' . $unit;
  ```
- 확신도: 확실
- 비고: 없음

### BR-11 태그는 이름으로 정확히 일치, 태그 하나만
- 규칙: 태그 값이 있으면, 그 이름의 태그가 연결된 문항만 조회한다.
- 근거: `search.php:244-245`, `:66-67`
- 근거 코드:
  ```php
  $where .= " AND EXISTS (SELECT 1 FROM item_tag it JOIN tag t ON t.id = it.tag_id"
          . " WHERE it.item_id = v_item_public.id AND t.name = ?)";
  ```
- 확신도: 확실
- 비고:
  - 태그는 한 개만 받는다. 배열로 오면 첫 값만 쓴다(BR-15).
  - 검색은 태그를 **이름**으로 찾고, 등록(BR-36)은 **id** 로 찾는다.
  - 실행 확인: `tag[]=계산&tag[]=개념` 은 `tag=계산` 과 같은 13건이다(9장 C12 · C13).

### BR-12 태그 이름은 50자까지
- 규칙: 태그 값이 50자를 넘으면 50자로 자르고 경고를 띄운다.
- 근거: `search.php:240-242`

  ```php
  if (mb_strlen($tag, 'UTF-8') > 50) {
  ```

- 확신도: 확실
- 비고: 50 은 `tag.name VARCHAR(50)`(`db/mariadb/init/01-schema.sql:37`)과 같은 값이지만, 코드에서는 따로 적은 매직 넘버다.

### BR-13 목록에 없는 태그는 경고
- 규칙: 입력한 태그 이름이 태그 선택 목록(`tag` 테이블)에 없으면 경고를 띄운다. 조회는 그대로 하며, 결과는 0건이다.
- 근거: `search.php:250-260`, `:178`
- 근거 코드:
  ```php
  if ($opt['value'] !== '' && $opt['value'] === $tag) {
  $warnings[] = '등록되지 않은 태그입니다: ' . $tag;
  ```
- 확신도: 확실
- 비고: 이 비교는 PHP `===` 라서 대소문자를 구분한다. SQL 비교(BR-11)는 콜레이션을 따른다. 그래서 경고가 떠도 결과가 나올 수 있다. 시드 태그가 모두 한글이라 대소문자 차이를 재현할 데이터가 없다. 그래서 여전히 **미확인**이다.

### BR-14 태그에 `%` · `_` 가 있으면 경고
- 규칙: 태그 값에 `%` 나 `_` 가 있으면 "부분 일치를 지원하지 않는다" 는 경고를 띄운다.
- 근거: `search.php:237-238`
- 근거 코드:
  ```php
  if (strpos($tag, '%') !== false || strpos($tag, '_') !== false) {
      $warnings[] = '태그는 부분 일치를 지원하지 않습니다.';
  ```
- 확신도: 확실
- 비고: 태그는 `=` 로 비교하므로 와일드카드로 동작하지 않는다. 반면 키워드(BR-07)는 와일드카드로 동작한다.

### BR-15 배열 파라미터는 첫 값만 사용
- 규칙: GET 파라미터가 배열로 오면(예: `tag[]=a&tag[]=b`) 첫 값만 쓴다.
- 근거: `search.php:51-80`

  ```php
  // 파라미터 꺼내기 (배열로 들어오면 첫 값만 쓴다)
  $tag = is_array($params['tag']) ? (string)reset($params['tag']) : (string)$params['tag'];
  ```

- 확신도: 확실
- 비고: 없음

## 2. 문항 검색 — 정렬 · 페이지 · 결과 표시

### BR-16 기본 정렬은 난이도 내림차순, 같으면 번호 오름차순
- 규칙: 정렬 기준이 비어 있으면 `level DESC, id ASC` 로 정렬한다.
- 근거: `search.php:317-320`
- 근거 코드:
  ```php
  // 기본 정렬: 어려운 문항부터, 같은 난이도면 번호 순
  $orderBy = " ORDER BY level DESC, id ASC";
  ```
- 확신도: 확실
- 비고: 이 정렬이 `default` 분기(`search.php:325`)에도 똑같이 한 번 더 적혀 있다.

### BR-17 알 수 없는 정렬 기준은 기본 정렬
- 규칙: 정렬 기준이 `id` · `title` · `unit` · `level` · `created` 중 하나가 아니면, 경고를 띄우고 기본 정렬(BR-16)을 쓴다.
- 근거: `search.php:266`, `:322-326`
- 근거 코드:
  ```php
  $warnings[] = '알 수 없는 정렬 기준입니다. 기본 정렬을 사용합니다.';
  $sort = '';
  $orderBy = " ORDER BY level DESC, id ASC";
  ```
- 확신도: 확실
- 비고: 정렬 기준은 소문자로 바꾸고 앞뒤 공백을 뺀 뒤 비교한다(`search.php:266`). 그래서 `ID` 도 `id` 로 인정된다.

### BR-18 정렬 방향은 asc · desc 만 인정
- 규칙: 정렬 방향이 `asc` · `desc` 가 아니면, 방향을 지정하지 않은 것으로 본다. 이때 값이 비어 있지 않았다면 경고를 띄운다.
- 근거: `search.php:267-273`
- 근거 코드:
  ```php
  if ($dir !== 'asc' && $dir !== 'desc') {
      if ($dir !== '') {
          $warnings[] = '정렬 방향은 asc 또는 desc 만 가능합니다.';
  ```
- 확신도: 확실
- 비고: 없음

### BR-19 정렬 기준별 기본 방향
- 규칙: 방향을 지정하지 않으면 `id` · `title` · `unit` 은 오름차순, `level` · `created` 는 내림차순으로 정렬한다.
- 근거: `search.php:277-315`, `:328-331`
- 근거 코드:
  ```php
  if ($dir === 'desc') {            // id · title · unit: desc 일 때만 내림차순
  if ($dir === 'asc') {             // level · created: asc 일 때만 오름차순
  $dir = ($sort === 'level' || $sort === 'created') ? 'desc' : 'asc';
  ```
- 확신도: 확실
- 비고: 같은 기본 방향을 두 번 따로 구현했다. 한 번은 SQL 분기의 `if` 방향(`:278`, `:286`, `:294`, `:302`, `:310`)이고, 다른 한 번은 화면 표시용 `$dir` 보정(`:330`)이다.

### BR-20 동순위는 번호 오름차순
- 규칙: 제목 · 단원 · 난이도 · 등록일로 정렬하면, 값이 같은 문항끼리는 `id ASC` 로 정렬한다.
- 근거: `search.php:287-313`
- 근거 코드:
  ```php
  $orderBy = " ORDER BY title DESC, id ASC";
  $orderBy = " ORDER BY created_at DESC, id ASC";
  ```
- 확신도: 확실
- 비고: 내림차순일 때도 2차 정렬인 `id` 는 오름차순으로 고정이다.

### BR-21 단원 정렬의 2차 기준은 난이도 내림차순 고정
- 규칙: 단원으로 정렬하면 방향과 상관없이, 같은 단원 안에서는 `level DESC` 다음 `id ASC` 로 정렬한다.
- 근거: `search.php:295`, `:297`
- 근거 코드:
  ```php
  $orderBy = " ORDER BY unit_code DESC, level DESC, id ASC";
  ```

## 7. 같은 규칙이 여러 곳에 다르게 구현된 곳

| 규칙 | 위치 | 차이 |
|---|---|---|
| 난이도 1~5 | 등록 `register.php:70` / 검색 `search.php:214-229` | 등록은 범위 밖 값을 거부한다. 검색은 빈값이면 5 를 빼고, 범위 밖 값은 `(int)` 로 바꿔 조회한다 |
| 공개 문항 = `status 'A'` | 뷰 `01-schema.sql:70` / `units.php:17` | 같은 조건을 두 번 구현했다. 단원 목록 건수는 난이도 5 를 포함하고, 기본 검색은 제외한다 |
| 단원 식별 | 검색은 `code` 로(`search.php:118`), 등록은 `id` 로(`register.php:62`) | 식별 키가 다르다 |
| 태그 식별 | 검색은 `name` 으로(`search.php:245`), 등록은 `id` 로(`register.php:77`) | 식별 키가 다르다 |
| 태그 존재 확인 | 검색은 PHP `===`(`search.php:253`), SQL 은 콜레이션 비교(`search.php:245`) | 대소문자 처리가 다를 수 있다(**미확인**, 시드 데이터로 재현 불가) |

## 8. 미확인

| 항목 | 이유 |
|---|---|
| `level < 5` 가 의도한 동작인지 버그인지 | 주석과 코드가 반대다. 시드 주석(`02-seed.sql:34`)은 이 동작을 전제한다. 기획 의도는 사람에게 물어야 한다 |
| 태그 이름 비교의 대소문자 구분 | 시드 태그가 모두 한글이라 재현할 데이터가 없다. 단원 코드는 구분하지 않음을 확인했다(9장 C4) |
| `R` → `A`, `D` 전이 규칙과 그 주체 | 이 모듈에 코드가 없다([ERD.md](ERD.md) 4장과 같음) |
